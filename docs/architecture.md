# Architecture

浏览器通过 Gateway 接入；Gateway 使用 Nacos 发现 core 与 commerce 的 HTTP 服务。commerce 通过 Dubbo 只读查询会话、用户和门店。资源授权在服务端校验，不信任客户端传入的身份。

普通购买以 MySQL 为权威，服务端校验 SKU 与报价版本并保存订单快照。订单、库存、模拟付款和凭证写入共享数据源与 Spring 本地事务。付款与关闭竞争待付款旧状态，只有实际关闭成功的路径释放库存；核销同样依赖状态条件与门店授权。

新活动秒杀在 Redis Lua 中保存资格、库存预占及恢复索引，再通过 RabbitMQ 异步落单。生产端检查 Confirm 与 Mandatory Return；消费事务提交后手动 ACK。发送结果不明保留预占依据，不直接回补；消费者重复执行由稳定预占身份、持久结果及数据库约束处理。

恢复扫描查询 Redis 预占账本，消费后的结果和同步待办写入 MySQL。数据库关闭与 Redis 回补不是一个原子事务，通过同步待办及幂等 Lua 继续处理。重试耗尽进入 DLQ 并不自动完成业务补偿。当前方案不是 MySQL Outbox，也不保证 Redis 账本永久丢失后可自动恢复。

旧券入口另外保留 IP / 用户双维 Lua 令牌桶。脚本读取 Redis 时间，按时间差补充令牌，先扣 IP 再扣用户；用户维度拒绝时不返还已扣的 IP 令牌。这与新商城秒杀预占是不同职责。

门店修改在数据库提交后删除实际命名空间的缓存键并同步 GEO。此方式减少提交前旧值回填，但不是强一致协议；并发旧读回填和删除失败仍有边界。
